# 完整技术栈与选型说明

> 本文覆盖系统实际使用的全部框架、中间件、算法与工程工具。
> 版本为 2026-10-24 本机验证版本，升级依赖后以 `pom.xml` / `package.json` / `requirements*.txt` 为准。

## 1. 总体分层

```text
展现层    Vue 3 + TypeScript + Element Plus + ECharts
             │ REST / WebSocket / MJPEG
业务层    Spring Boot 3 + Spring Security + MyBatis-Plus
             │ HTTP / RabbitMQ
算法层    FastAPI + PyTorch + Ultralytics YOLOv8 + ByteTrack + OpenCV
             │ JDBC / Redis / MQ
数据层    H2 / MySQL + Redis + RabbitMQ + 本地截图目录
部署层    Docker Compose + Nginx + Maven / npm / uvicorn
```

## 4. 算法与视觉技术栈

| 技术 | 版本 | 用途 |
| --- | --- | --- |
| Python | 3.12.14 | 算法服务运行时 |
| PyTorch | 2.6.0 | 深度学习推理 |
| Ultralytics | 8.4.185 | YOLOv8 训练、推理、导出 |
| YOLOv8n | - | PPE 检测基线模型 |
| COCO YOLOv8n | - | person 检测，用于人数与入侵 |
| ByteTrack | Ultralytics 内置 | 多目标跟踪、trackId |
| OpenCV | 4.10.0.84 | 拉流、解码、绘制、JPEG 编码 |
| NumPy | 2.5.4 | 图像矩阵运算 |
| FastAPI | 0.115.6 | 算法服务 REST 接口 |
| Uvicorn | 0.34.0 | ASGI 服务器 |
| Pika | 1.3.2 | RabbitMQ 发布客户端 |
| Requests | 2.32.3 | 同步后端配置、上报事件 |
| python-multipart | 0.0.20 | 图片上传 |
| lap | 0.5.13 | ByteTrack 匈牙利匹配依赖 |

算法链路：

1. `StreamManager` 每 20 秒同步摄像头 / 区域 / 规则，自动启停线程
2. `CameraWorker` 拉流 → 抽帧 → 双模型推理（PPE + COCO person）
3. ByteTrack 分配 trackId，PPE 与 person 的 ID 做偏移避免冲突
4. 规则引擎依次执行：置信度 → ROI → 连续帧 → 冷却 → 幂等
5. 标注帧编码为 MJPEG，同时保存告警截图
6. 事件通过 HTTP 或 RabbitMQ 上报，失败自动回退

## 6. 关键设计

| 设计 | 说明 |
| --- | --- |
| 算法/业务分离 | Python 专注推理，Spring Boot 专注业务，HTTP/MQ 解耦 |
| 双模型融合 | PPE 模型负责安全帽/反光衣，COCO 模型补足 person，降低入侵漏检 |
| ROI 多边形 | 百分比坐标，射线法判断脚点是否在危险区域内 |
| 连续帧投票 | 连续 N 帧命中才告警，抑制单帧误检 |
| 冷却时间 | 按 trackId + 行为去重，避免同一目标刷屏 |
| MJPEG | 服务端绘制检测框，浏览器直接展示，天然对齐 |
| 幂等接入 | `alarmNo` 唯一索引，MQ 重试不产生重复告警 |
| 降级策略 | 无权重→DEMO；无 Redis→内存；MQ 失败→HTTP；无 GPU→CPU/MPS |
| 地址脱敏 | 列表脱敏、详情鉴权、更新防覆盖，支持开关 |

## 7. 为什么没有使用某些技术

| 技术 | 不采用原因 |
| --- | --- |
| Spring Cloud（Nacos/Gateway/Sentinel） | 单人毕设部署与联调成本高；当前「模块化单体 + 独立算法服务」已体现拆分思想 |
| Hadoop / Spark / Flink | 与实时视频检测主链路关联弱，增加环境成本；统计用 MySQL 聚合即可 |
| UniApp 小程序 | 属于加分项，当前接口已具备扩展条件，优先保证 PC 端完整闭环 |
| WebRTC | 需要信令与转码服务，MJPEG 更适合快速演示与检测框叠加 |
| 前端目标检测（TensorFlow.js） | 浏览器算力有限，无法支撑多路 1080p 实时推理 |

## 9. 技术亮点（答辩可讲）

1. **检测 + 跟踪 + 区域规则融合**：不是单纯跑 YOLO，而是把跟踪 ID、ROI、连续帧、冷却组合成告警引擎。
2. **双模型互补**：PPE 数据集人体框不完整，增加 COCO person 模型，兼顾安全帽识别与入侵判定。
3. **算法/业务解耦**：FastAPI 与 Spring Boot 独立部署，HTTP/MQ 双通道，MQ 故障自动回退。
4. **工程化降级**：H2/MySQL、内存/Redis、HTTP/MQ、GPU/CPU 全部可切换，保证答辩现场可运行。
5. **隐私与合规**：地址脱敏、密码哈希、日志不落请求参数、演示视频人脸模糊。
